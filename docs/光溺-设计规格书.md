# 《光溺》DROWNLIGHT · 设计规格书

- **版本**：v1.0
- **状态**：**设计定稿**（A~J 全部确认，可进入实现阶段）
- **形态**：Windows 桌面客户端 `光溺.exe`（.NET Framework 4.8 + WebView2 外壳，内部是原生 Canvas 2D + WebAudio，零素材、零依赖）
- **目标平台**：仅 Windows 10/11 客户端，不再维护网页版
- **目标单局时长**：约 18 分钟（通常死亡在第 3~4 层）
- **项目目录**：仓库根目录（`index.html` 所在的那一层）

## 0. 一页摘要

> 深度 4000 米，无光带。你的灯是这片海里唯一的光源，也是唯一的诱饵。
> 在这里，发光意味着被看见，被看见意味着被吃掉。

你驾驶一台微型深潜器向深渊下潜。屏幕几乎全黑，视野只有一道探照灯锥、身边 200px 的微弱生物荧光，以及每 2.4 秒扫过一次的声呐。敌人藏在黑暗里，只亮着各自的发光器官。

每一层 = 3 个涌潮，每个涌潮结束从三张卡里选一张强化自己；每层末尾有一个全新的 Boss。你唯一的目标是更深——死亡时探测器会在深海水压下内爆。

**四根设计支柱：**

1. **光就是玩法**。看得见多少，决定你能活多久。
2. **信息分层**。灯光（实时、精确、短程）与声呐（滞后、模糊、全图）互不替代。
3. **攻击必先发光**。看不见敌人，但永远看得见威胁。
4. **死亡是熄灭**。所有敌人死亡都是光消失，不是爆炸。

## 1. 主题与美术（A）

### 1.1 世界观

只有一句话，不做剧情、不做文本、不做动画演出（除开场与结局）：

> 深度 4000 米，无光带。你的灯是这片海里唯一的光源，也是唯一的诱饵。

它只承担功能：让"为什么玩家一直在发光""为什么敌人总是冲过来"自洽。

### 1.2 玩家形象

**单人微型深潜器（ROV）**：半球形耐压壳 + 一根探照灯臂 + 尾部推进器。

选它而非"发光鱼"的原因：它天然带有三个可读的视觉组件——**朝向、灯、推力**。

### 1.3 色彩语义

颜色承担信息，不是装饰。

| 颜色 | 色值 | 含义 | 用在哪 |
|---|---|---|---|
| 墨青（背景） | `#03101a` → `#07242b` | 环境 | 背景渐变，永不参与战斗信息 |
| 荧光青绿 | `#3ef0c8` | 玩家 / 友方 / 可拾取 | 灯锥、玩家子弹、强化道具 |
| 品红 | `#ff4fa3` | 敌人 / 伤害 | 敌人发光器官、敌弹、血条 |
| 金 | `#ffce5c` | 收益 / 爆发 | 击杀闪光、连击数字、稀有卡 |
| 深紫 | `#6a3cff` | 精英 / Boss / 传说 | Boss、传说卡 |
| 骨白 | `#eafcff` | 命中 | 单帧闪白 |

**铁律**：青绿永不出现在敌人身上，品红永不出现在玩家身上。玩家在满屏光效里靠颜色就能瞬间定位自己。

### 1.4 敌人发光语言

**敌人不是通体发光的色块，而是黑暗中一个亮着的器官。** 这是本作视觉格调的关键。

| 敌型 | 视觉主体 | 唯一发光处 |
|---|---|---|
| 灯笼鱼 | 獠牙剪影 | 头顶诱饵灯（一明一暗） |
| 水母 | 半透明伞盖 + 摆动触须 | 伞盖边缘一圈脉动蓝光 |
| 乌贼 | 细长流线体 | 两条眼纹 |
| 管虫 | 从边缘伸出的管状体 | 顶端羽状鳃 |
| 斧头鱼 | 薄片状 | 腹部一排光点 |
| 鮟鱇（精英） | 漆黑身体 | 口腔内部 |

### 1.5 画面分层

| 层 | 内容 | 动效 |
|---|---|---|
| L0 | 垂直深海渐变 | 静止 |
| L1 | 海雪（marine snow，300~500 微粒，3 层视差） | 缓慢上浮 + 正弦横摆 |
| L2 | 远景剪影（岩壁、沉船、鲸骨） | 极慢平移，0.05 视差 |
| L3 | 战斗层 | 实时 |
| L4 | 光效层（加色混合） | 实时 |
| L5 | 前景（呼吸暗角 + 水下折射波纹） | 缓慢 |

L1 与 L2 提供参照物——纯黑背景在高速移动时会让玩家失去方向感，海雪让移动立刻有实感。

### 1.6 氛围手段

- 全场发光体亮度同步 0.2Hz 缓慢脉动，像深海本身在呼吸
- 波次之间完全安静，只有海雪与低频心跳脉冲
- 快速移动时海雪与远景反向流动，制造水阻感
- 远处鲸歌随机 40~90 秒一次

## 2. 可见度系统（核心机制）

### 2.1 光照物理规则

> 弱光被海水吸收，强光穿透黑暗。

- **弱光**（敌人本体荧光）随距离衰减：**200px 内**可见亮点与极淡轮廓；**超过 200px 完全消失**
- **强光**（攻击蓄力、弹幕、爆炸、Boss 核心）**全屏可见**，任何距离

这条规则一次性解决公平性：**你看不见敌人，但永远看得见威胁。**

### 2.2 三层信息模型

| 通道 | 性质 | 回答的问题 |
|---|---|---|
| 灯光 | 实时、精确、短程 | 这个要怎么打、怎么躲 |
| 声呐 | **滞后**、模糊、全图 | 有没有东西正在靠近 |
| 强光预警 | 即时、全屏 | 现在马上要挨打了 |

### 2.3 灯锥

- 长度 **340px**、张角 **52°**，柔和边缘
- 跟随鼠标，**云台惯性约 0.1 秒**到位；子弹方向 = 灯锥当前方向
- 锥内**完全显形**（轮廓、朝向、大小）
- 锥外压暗到 **45%**，不是纯黑
- 血量低于 40% 时灯锥变暗、闪烁、偏冷色
- 冲刺瞬间拉长成一道光束

### 2.4 声呐环

声呐不是 UI 特效，而是**世界里真实扩散的一道环**。

- 每 **2.4 秒**，一圈淡青光波从探测器向外扩散，约 0.9 秒扫过全屏
- 扫过敌人身体时，该敌人**闪现 0.35 秒剪影**
- 环扫过声呐盘时，盘上光点在同一时刻更新并开始淡出

**小地图与主画面是同一件事的两种投影。**

### 2.5 主动声呐（ping）

- 按键：`Q` / 右键 / 触屏圆钮
- 立即发射全屏扫描，声呐盘瞬间全亮
- **冷却 4 秒**
- **代价：全部电力被抽走，灯锥在 0.15 秒内收缩熄灭，0.8 秒后重新点亮**（有灯丝重新亮起的闪烁）

操作等式：**冲刺 = 用位置换生存；声呐 = 用视野换情报。**

### 2.6 击杀照明

> **每次击杀，爆炸的光短暂照亮周边 260px（0.25 秒）。**

战斗越激烈，画面越亮。形成"用死亡点亮黑暗"的节奏，同时是连击系统的视觉载体（连击越高，光照越久、越偏金）。

### 2.7 屏幕外敌人

- 完全不可见，只靠声呐
- 从边缘进入时 **0.35 秒**轮廓淡入
- 贴边但看不见的敌人：屏幕对应边缘出现**极淡品红呼吸光晕**（宽约 120px），暗示"水体被搅动"

## 3. 核心循环与进度（B）

### 3.1 一句话

> 下沉 → 涌潮 → 升级 → 更深 → 死亡。

### 3.2 术语与结构

- **涌潮 Surge**：45~75 秒的敌潮，有固定配额（刷完且清空即结束）→ 结束给 **三选一（普通池）**
- **层 Layer**：3 个涌潮 + 层尾 Boss，约 3~5 分钟 → 结束给 **深度跃迁 + 三选一（稀有池）**

### 3.3 单层时间轴（以第 1 层为例，约 4 分钟）

```
00:00  下潜过场  深度 0000 → 0410m，灯光亮起            8s
00:08  涌潮 1   配额 18 只，1 种敌型                    55s
01:03  ▸ 三选一 三张卡浮出，世界完全暂停
01:10  涌潮 2   配额 24 只，2 种敌型                    65s
02:15  ▸ 三选一
02:22  涌潮 3   配额 30 只，2 种敌型 + 首次精英          70s
03:32  ▸ 层尾 Boss
04:17  ▸ 深度跃迁过场 + 稀有池三选一
04:35  进入第 2 层
```

### 3.4 开场：海上投放（7 秒，任意键跳过）

| 时间 | 画面 | 声音 |
|---|---|---|
| 0.0–0.8 | 全黑，极淡水面反光 | 海浪、风、吊机 |
| 0.8–2.2 | 俯视深夜海面，母船探照灯扫过波纹，投放舱打开 | 液压开盖、蜂鸣 |
| 2.2–3.0 | 探测器脱钩下坠、入水、水花与气泡 | 入水闷响 |
| 3.0–5.0 | 跟随下潜，水色青绿→墨蓝→黑，灯锥由暗到亮 | 水压渐强 |
| 5.0–6.0 | 深度表 0000 → 0410 滚动 | 第一声 ping |
| 6.0–7.0 | 远处黑暗中一对诱饵灯亮起又熄灭 | 静默 |

最后那一对诱饵灯就是开场教给玩家的第一条规则。

### 3.5 深度系统

- **唯一的进度单位**：每层跃迁 +350~700m
- **同时是分数倍率**：`1 + 深度 / 1000`（4000m 时 ×5）
- **也是难度可视化**：深度计颜色随深度变化（青绿 → 金 → 品红）
- **只增不减**（单程下潜）

### 3.6 死亡：内爆

深海高压下，耐压壳的真实破坏形态是**内爆**。

| 阶段 | 时长 | 表现 |
|---|---|---|
| 1 失压 | 0.12s | 时间放慢至 0.25 倍，所有声音抽走只剩心跳 |
| 2 塌缩 | 0.25s | 船体向中心缩到 15%，外壳凹痕，灯光剧烈闪烁 |
| 3 闪白 | 0.08s | 全屏爆白，一声极短的气泡爆裂 |
| 4 爆散 | 1.2s | 冲击波环、金属碎片、气泡柱向上升 |
| 5 熄灭 | 0.6s | 灯锥最后闪一下，暗掉 |
| 6 静默 | 1.5s | 纯黑，只有低频水压声，然后结算淡入 |

死亡后**不放音乐**，只留水声。

### 3.7 通关

- 第 6 层击败「光溺」= 通关，进入结局演出
- 通关一次后解锁**无尽深渊**模式

## 4. 操作与手感（C）

### 4.1 输入总表

| 动作 | 键鼠 | 触屏 | 手柄 |
|---|---|---|---|
| 移动 | WASD / 方向键 | 任意位置按下生成虚拟摇杆 | 左摇杆 |
| 瞄准（灯锥） | 鼠标位置 | 自动锁定最近敌人 | 右摇杆 |
| 开火 | **自动** | 自动 | 自动 |
| 冲刺 | `Space` / `Shift` | 右下圆钮 / 双击 | RT |
| 主动声呐 | `Q` / 右键 | 右下圆钮 | LB |
| 暂停 | `Esc` / `P` | 左上角按钮 | Start |
| 静音 | `M` | — | — |
| 选卡 | `1/2/3` 或点击 | 点击 | 十字键 + A |

**不设手动开火。** 准星就是灯锥，你照到哪打到哪；多一个扳机键只会分散走位注意力。

### 4.2 移动模型

有惯性，但绝不迟钝。

| 参数 | 值 |
|---|---|
| 最大速度 | 320 px/s |
| 加速度 | 4200 px/s²（约 0.08 秒到全速） |
| 松手阻尼 | `v *= exp(-14·dt)`（全速到停约 0.22 秒） |
| 对角 | 归一化 |
| 转向倾斜 | 最大 8° |

刹得住，但会滑：0.22 秒滑行约 22px——刚好够感到船的分量，又不会因刹不住撞弹幕。

### 4.3 瞄准

- 灯锥云台惯性约 0.1 秒到位，不影响精度但带来重量感
- **自动瞄准兜底**：连续 3 秒无鼠标输入 → 自动锁定最近敌人；鼠标一动立即交还控制
- 灯锥内加一道极淡的体积光

### 4.4 冲刺

| 参数 | 值 |
|---|---|
| 距离 | 144 px（1200 px/s × 0.12s） |
| 冷却 | 1.1 秒 |
| 无敌帧 | 0.2 秒 |
| 方向 | 有输入朝输入方向；**无输入则朝瞄准反方向后撤步** |

冲刺表现：灯锥瞬间拉长成光束、推进尾迹发光、周围海水推开一圈水纹。

### 4.5 触屏方案

1. **虚拟摇杆**：任意位置按下生成，死区 8px，最大半径 70px，幅度控制速度
2. **船体视觉位置右上方偏移 60px**（手指不挡船）
3. 强制自动瞄准
4. HUD 上移 110px；声呐盘缩至 78px；冲刺/声呐按钮为两个 64px 圆钮固定右下

### 4.6 手感细节清单

- **输入缓冲**：冷却结束前 0.15 秒内按下冲刺 → 记住并在可用瞬间触发
- **贴边缓冲**：撞边界时柔和水流阻力 + 3px 回弹
- **受击反馈**：0.06 秒冻结帧 + 全屏轻微泛红 + 船体闪白 + 震屏 12
- **击杀反馈**：普通 0.03 秒冻结帧；Boss 0.25 秒慢放 + 白闪
- **推进尾迹**：速度越快，气泡与尾焰越密
- **静止不空转**：停住时船体随水流浮动 ±2px
- **边界水纹**：靠近边缘时出现极淡流动光带

### 4.7 相机

- **无相机跟随**，场地就是一屏
- 只有三种镜头动作：受击震屏、Boss 出场震屏、深度跃迁轻微缩放（1.0 → 1.04 → 1.0）
- 边界不可见，只有水流反馈（不画硬墙）

### 4.8 可及性

| 项 | 范围 | 默认 |
|---|---|---|
| 闪光强度 | 0–100% | 70% |
| 震屏强度 | 0–100% | 100% |
| 灯锥亮度 | 0–100% | 100% |
| 自动瞄准 | 开/关 | 开 |
| 色觉辅助 | 开/关 | 关 |

## 5. 玩家能力与构筑（D）

### 5.1 基础面板

|---|---|
| 船体完整度 | 4 格 |
| 基础伤害 | 10 / 发 |
| 射击间隔 | 0.135 秒（≈7.4 发/秒） |

### 6.9 Boss 池（12 个 · 每局随机 6 个）

|---|---|---|---|---|
| 1 | **荧**（巨型水母） | 半径 90，4 条长触手 | 环形弹幕 + 触手横扫切断移动路线 | 读弹幕 |

| 2 | **潮**（潮汐母体） | 水囊 + 三层潮汐弧 | **闭环浪墙只留一道缺口**，缺口每波转向；同时刷磷虾群 | 找开口 |
| 3 | **灯**（鮟鱇王） | 巨大诱饵灯悬于玩家上方 | **假光点**诱导 + 吸入 + 咬合 | 判断真假 |

| 4 | **群**（管虫珊瑚） | 中央母体 + 四角炮茧 | **部位拆解**，本体始终可受伤但减伤 20% | 处理看不见的边缘 |

| 5 | **晶**（结晶海葵） | 六边形结晶 + 6 枚公转晶簇 | 晶簇各自开火，本体吐螺旋；**晶簇全碎则停摆、本体受伤 ×1.5**，6.5 秒后长回来 | 分配火力 |

**Boss 骨架复用**：多部位受击、阶段切换（无敌帧 + 冲击波 + 演出）、血条与阶段刻度、死亡演出、出场演出由共享骨架提供；每个 Boss 只写自己的独有机制与绘制。

**血量按层折算，而不是按 Boss**：`T.boss.rankHp` 给出第 1~6 层应有的基准血量，
每个 Boss 用自己的 `hp / rankHp[rank]` 折算。所以 800 血的「荧」排到第 6 层就是 3800 血，
3800 血的「光溺」排到第 1 层也只有 800 血 —— 威胁等级决定它在名单里的位置，层数决定它的强度。

**Boss 时长目标**：12~25 秒。

### 6.10 无尽深渊

- 层数不封顶；**每 6 层算一轮**，每轮重新抽一批 6 个 Boss（换批时优先避开上一轮刚打过的）
- 血量：每轮 ×1.55，轮内每层再 ×1.055；弹速随层数缓涨（`T.scale.bspd` 上限 1.12）
- 无尽里不再判定通关，第 6 层打完直接继续第 7 层；结算页列出本局遭遇过的 Boss
- 深度超过 10⁴ m 后转科学计数法显示

## 9. 技术规格（H）

### 9.1 交付形态

**拆分为多个文件**，仍可直接双击 `index.html` 运行。

| 项 | 规格 |
|---|---|
| 运行方式 | 双击仓库根目录的 `index.html` |

| 环境 | Chrome / Edge 90+、Safari 15+、Firefox 90+ |
| 需能力 | Canvas 2D、WebAudio、localStorage |

> **不使用 ES Module**——因为 `file://` 协议下 ES Module 会被 CORS 拦截，双击就打不开了。

### 10.6 关于「结构支节点 6」的决策记录

曾讨论过的替代方案：**「光学卫星」**——一颗环绕玩家公转的小型卫星，提供移动照明（110px 光斑）与自动攻击（35% 伤害 / 0.55s 间隔），作为元进度的机制型奖励。

**最终结论：不采用。** 节点 6 维持原案 **最大船体 +1**。理由：

- 元进度保持"纯数值"的克制，机制型奖励留给局内的传说卡（「伴航无人机」已覆盖"环绕物"这一幻想）
- 血条 +1 是本作最朴素也最被低估的奖励——本作伤害恒定 1 格，多一格血等于整局容错率提升，分量足以支撑 750 数据的价位

> 备注：玩家的碰撞箱恒为半径 12px 的圆，**不随任何升级变化**。"船体"在本作中始终指血条上限，不指体积。

## 13. 实现说明与偏离

以下是与文档不一致或文档未覆盖、由实现阶段决定的项，**以代码为准**。

### 13.1 涌潮的判定方式

文档写的是「固定配额，刷完且清空即结束」。实现时发现：配额 18~38 只按正常刷怪节奏只能撑 20~30 秒，达不到设计的 45~75 秒。改为：

> **涌潮 = 固定时长（`38 + 层数×6`，上限 75 秒） + 同屏上限**

- 时长内按三段式节奏持续刷新，把同屏敌人维持在 `10 / 13 / 16 / 19 / 22 / 25` 的上限附近
- 时长走完后停止刷新，剩余敌人全体亮灯，清空即结束
- 兜底：若 15 秒后仍未清空，剩余敌人自行散开（不计分），保证涌潮一定结束

实测每层 3 个涌潮约 2~3 分钟，六个 Boss 合计约 2 分钟，一局约 15~18 分钟，符合目标。

### 13.2 数值调整

| 项 | 文档 | 实现 | 原因 |
|---|---|---|---|
| 同屏敌人上限 | 8~18 | 10~25 | 原值画面过空 |
| Boss HP | 900 / 1800 / 3000 / 4200 / 5600 / 7800 | 800 / 1300 / 1800 / 2000 / 3000 / 3800 | 原值为「目标时长」推算有误，实测超时 2~4 倍 |
| 玩家开火后坐 | 船体后坐 2px | 纯视觉位移，不产生速度 | 速度后坐会让站着不动的玩家被推着漂 |
| 子弹/敌弹辉光 | 逐颗径向渐变 | 两层圆 + 加色混合 | 每帧数百个渐变会掉帧 |

### 13.3 Boss 4「群」的炮茧

文档写「炮茧全部拆掉后本体暴露」。实现时发现两个问题：炮茧在四角，自动瞄准会只锁本体；若玩家不手动点掉炮茧，战斗会永远打不动（软锁）。

**改为**：炮茧是**额外的炮台压力**，本体始终可受伤，但炮茧存活时本体减伤 20%。炮茧仍可被打掉（每个 +300 分），打掉后压力骤减。机制保留，软锁消除。

### 13.4 其他实现细节

- 自动瞄准：连续 3 秒无鼠标输入时接管，鼠标一动立即交还（文档 4.3 已写）
- 冲刺与 ping 都做了「按住不重复触发」的边沿检测
- 声呐扫描的显形效果按**距离延迟**触发（波前扫到才亮），而不是全场同时闪
- 触屏时声呐盘缩小并上移，右下角留出冲刺 / 声呐两个圆钮
- 调试面板与 URL 参数见 `README.md`

### 13.5 已知可改进项

- 远景剪影的轮廓偏硬，可以加高斯模糊做成真正的失焦感
- 灯笼鱼在中距离只看得见一个光点，辨识度一般，可考虑加一条更明显的轮廓边光
- 音乐只有一条 drone + 脉冲，Boss 层还可以做得更有辨识度
- 卡牌图标是通用几何符号，与实际效果只是弱对应

## 15. v1.4 全屏、指针锁定、独立 exe

### 15.1 问题

在浏览器里玩时，鼠标大幅甩动会移出网页区域，光标飘到浏览器外面，灯锥随即失控。

### 15.2 全屏

- 页面任意一次按键 / 点击都会尝试进入**全屏**（浏览器规定必须由用户手势触发）
- `F` / `F11` 切换
- 用户按 `Esc` 主动退出全屏后不再自动重进

### 15.3 指针锁定（Pointer Lock）

进入战斗时请求锁定鼠标：

- 锁定后鼠标移动用 `movementX/Y` 累积成**虚拟光标**，并被钳制在窗口内——怎么甩都不会飘出去
- 瞄准灵敏度可在设置里调（0.5× ~ 1.5×，默认 1.0×）
- 锁定时**关闭自动瞄准兜底**，否则停下 3 秒准星会自己跑掉
- 画面增加准星：环形 + 四向刻度 + 一条极淡的、指回自己的线，大幅甩动后能立刻找回
- 锁定状态下解除锁定（如按 `Esc`）会**自动暂停**
- 若浏览器拒绝锁定，自动回落到绝对坐标瞄准，不影响游玩

### 15.4 独立 exe

`光溺.exe`，约 1.1 MB，单文件。

| 项 | 做法 |
|---|---|
| 外壳 | C# WinForms（.NET Framework 4.8，Windows 自带编译器可直接编译） |
| 渲染 | WebView2（系统自带 Chromium 运行时，Win10/11 预装） |
| 游戏文件 | 全部内嵌为资源，首次运行解到 `%LOCALAPPDATA%\Drownlight\app` |
| 页面来源 | `SetVirtualHostNameToFolderMapping` 映射成 `https://drownlight.local`，保证 localStorage 正常 |
| 全屏 | 监听 `ContainsFullScreenElementChanged`，网页里的 Fullscreen API 直接驱动窗口全屏 |
| 开发模式 | `--dev` 直接读 exe 同目录源码，改完刷新即生效 |
| 自检 | `--selftest out.png --query "?auto=1&sim=600"` 无头截图，用于回归验证 |

构建脚本 `build\build.ps1`，不依赖任何需要联网安装的工具链。

## 16. v1.5 音乐、自机可读性、UI 手感

### 16.1 音乐重做（四层）

原来的音乐只有一条 drone + 一个节拍脉冲，打 Boss 也只是换个更快的音。改成四层结构，每层都有自己的进入条件：

| 层 | 内容 | 进入条件 |
|---|---|---|
| **次低音** | 41Hz 双正弦（略微失谐） | 全程 |
| **和声 pad** | 小三和弦（55/65.4/82.4/110Hz），经低通滤波，0.06Hz 呼吸 | 全程，深度越大越暗越低沉 |
| **水流** | 循环噪声 + 带通 | 全程 |
| **战斗层** | 90BPM 心跳底鼓 + 五声音阶琶音 | 强度 > 0.12，音量随强度上升 |
| **沙锤** | 高通噪声 | 强度 > 0.42 |
| **Boss 层** | 八分音符锯齿贝斯（含小二度进行的固定音型）+ 每 3.9 秒一次不和谐刺 | Boss 战 |

另外加了两个转场：

- **Boss 登场**：1.1 秒噪声上扫（380→5200Hz）+ 次低音冲击，制造“压下来”的感觉
- **Boss 死亡**：低频坠落 + 噪声下扫

强度值来自「敌人数量 + 连击 + Boss 在场 + 血量危险度」，所以打得越凶，层次堆得越满。

### 16.2 自机重做

原来自机只是一个 17px 的小三角，满屏光效时几乎找不到。现在：

- **分段圆环 = 血条**：船体周围 4 段圆弧（随最大船体数变化），亮起的段数就是剩余格数，颜色随血量比从青绿 → 金 → 红，血量低时整环随心跳闪烁
- **正前方的亮弧**：永远指出灯锥朝向，静止时也能看出面向哪
- **暗底托盘**：船体下方压了一圈暗色渐变，避免被自己的灯锥洗掉
- **残影**：高速移动时拖出三道递减的圆环
- **更清晰的船形**：对称飞镖形 + 侧鳍 + 中脊 + 座舱高光，比原来大 12%
- **护盾 / 无敌帧**：护盾是外层细环，无敌帧是闪烁的白色虚线环

### 16.3 UI 交互反馈

- **鼠标悬停即高亮**：按钮放大描边、左侧出现指示条、背景发光；选卡界面悬停即选中，技能树悬停即预览
- **悬停音效**：进入新元素的瞬间一声极轻的“嗒”（同一帧内不会重复播放）
- **点击涟漪**：点击位置扩散两圈同心圆，0.55 秒淡出
- **按下反馈**：命中的按钮内缩描边 + 背景加亮 0.16 秒
- 键盘操作保留原有的选中高亮，两者互不冲突

v1.5 及之前，「打穿第 6 层」走的是 `updateSurge → goto('ending')`，完全绕开了 `playerDie()` —— 而残骸数据只在 `playerDie()` 里结算。结果：

- 通关后结算页显示 `+0`，技能树的点数没有增加
- `totalDives` / `bestDepth` / `bestScore` 也一并漏记
- 「无尽深渊」的解锁写在结局动画第 14.5 秒，提前退出就丢

修法：把结算抽成 `DL.awardRun(cleared)`，死亡与通关共用，并用 `G.awarded` 做幂等（重复调用不会二次入账）。

| 项 | 公式 |
|---|---|
| 基础 | `深度/10 + 击杀×1 + (层数−1)×60 + ⌊深度/500⌋×20` |
| 通关奖励 | `900 + 层数×220`（第 6 层 = 2220） |
| 一次满通关 | 约 3200–3300 |

通关同时写入 `clears++` 与 `endless = true`，不再依赖结局动画播完。结算页会单独标出「含通关奖励 +N」和「技能树可用 N」。

### 17.2 渲染性能

弹幕密集时掉帧的根因是**每帧的 Canvas2D 调用次数与填率**，不是逻辑。逐项处理：

| 项 | 之前 | 现在 |
|---|---|---|
| 发光 | 每次 `createRadialGradient` + `arc` + `fill` | 128px 贴图缓存 + `drawImage`（每帧省掉 60+ 次渐变创建） |
| 灯锥 | 每帧新建 9 个径向渐变 | 渐变按长度缓存，逐片只改 `globalAlpha` |
| 弹幕 | 每颗弹 3 次 `fill` | 同透明度的圆合并成一条路径，一次 `fill`（90 颗 = 3 次而不是 270 次） |
| 敌弹 | 每颗 2 次 `fill` | 同上，200 颗 = 2 次 |
| 粒子 | 每颗粒子 `arc` + `fill` | 半径 < 2.4px 改用 `fillRect`；海雪同理 |
| 背景 / 暗角 | 每帧两次全屏渐变求值 | 烘成半分辨率贴图，每帧一次 `drawImage` |
| 颜色字符串 | 每次 `U.rgba` 拼新字符串 | 按 (颜色, 1/200 透明度) 缓存 |
| 字体字符串 | 每次 `D.text` 拼新 font | 按 (字号, 字重) 缓存 |
| 音效 | 每颗子弹、每次命中都发声 | 同类型音效节流（射击 55ms / 命中 45ms / 击杀 40ms） |

另外加了两层保险：

1. **像素预算 `T.perf.maxPixels = 4.0e6`**：窗口 × DPR 超过 400 万像素就等比降采样，大屏 4K 不会让填率翻四倍。
2. **自适应分辨率**：FPS 持续 1.5 秒低于 52 就把内部分辨率按 12% 往下调（最低 65%），连续 6 秒稳定 57+ 再逐步升回。按 `F1` 可以在调试面板里看到实时 FPS、峰值帧时长和当前画质百分比。

### 17.3 静止画面混音

「UI 选择和暂停时的音乐刺耳」来自三处：

- **菜单音效**：`click` 原来是 880Hz **方波**（方波=大量奇次谐波，天生刺），`hover` 是 1500Hz 高频正弦。现在全部换成正弦/三角并压低声压：`click` 600→460Hz 三角波，`hover` 820Hz、音量 0.014。
- **次低音的“打摆”**：原来是 41Hz 与 41.7Hz 两个正弦，差频 0.7Hz，低频上表现为周期性鼓胀；改成 41Hz + 61.74Hz（纯五度），去掉拍频。
- **小三度的粗糙感**：55/65.41Hz 相差 10.4Hz，在小音量、无节奏掩护的静止画面里最明显。三度电平从 0.30 降到 0.14，五度提到 0.34，保留阴暗但不糙。

结构上新增**场景混音** `DL.audio.scene('play'|'menu')`，由 `UI.goto` 统一驱动：

| | play | menu（标题/暂停/选卡/结算/设置） |
|---|---|---|
| 音乐总线 | 100%，低通 3400Hz | 55%，低通 1150Hz |
| 次低音 | 0.46 | 0.13 |
| pad | 0.17 | 0.13 |
| 水流 | 0.035 | 0.05 |

Boss 的不和谐刺也顺带收了：低通 900→420Hz，时长 0.5→0.42 秒，音量 0.045→0.03。

## 18. v1.7 全屏控制权收回宿主

### 18.1 问题

上一版进游戏用 `document.documentElement.requestFullscreen()`，exe 里靠 WebView2 的 `ContainsFullScreenElementChanged` 把窗口切成无边框。问题在于：**Chromium 把 Esc 硬编码成「退出全屏」**，页面拦不住 `preventDefault` 也没用。于是每次按 Esc 暂停，窗口都会掉回带边框的最大化，沉浸感直接断掉。

### 18.2 方案：全屏归宿主，页面只发请求

exe 里不再碰 DOM Fullscreen API，改成页面 `postMessage` → 宿主窗口：

```
页面 FS.tryEnter()  --postMessage('fs:1')-->  宿主 SetFullscreen(true)
页面 FS.exit()      --postMessage('fs:0')-->  宿主 SetFullscreen(false)
宿主 F11            --ExecuteScriptAsync-->  页面 FS.setFromHost(on)
```

没有 DOM 全屏，Chromium 就没有「全屏」可退：

- `Esc` → 只解除指针锁定 → 页面照常暂停，**窗口保持无边框全屏**
- `F` / `F11` → 唯一的全屏开关，双向同步状态
- 用户主动退出过全屏后置 `FS.userOff`，下一局开局不会再把窗口抢回全屏

页面侧 `FS.host` 由 `window.chrome.webview.postMessage` 是否存在判定：exe 走宿主通道，浏览器继续走 Fullscreen API（网页里 Esc 退全屏是浏览器行为，无法拦截，暂停页的提示文案会相应变化）。

`F1` 调试面板新增 `全屏 开/关`，用来确认当前状态。

### 18.3 附带

- 开局（`beginPlay`）自动请求全屏，不再依赖「首次点击」触发
- exe 新增 `--probe <file> --probejs "<js>" --probewait <ms>` 与 `--shotwait <ms>`，可以在指定时刻把页面状态/截图落盘，方便无头验证

## 19. v1.8 标题界面的退出游戏

标题菜单从 5 项加到 6 项，最后一项是 **退出游戏**（副标题在 exe 里显示「关闭窗口」，网页里显示「关闭标签页」）。键盘上下循环同步改成 6 项，`Enter` 同样可用。

实现：

```
页面 DL.quitGame()  --postMessage('quit')-->  宿主 Quit()
```

宿主的 `Quit()` 用 `BeginInvoke` 把关闭动作排到当前消息之后（不能在 WebView2 自己的回调里 Dispose 控制器），然后 `wv.Dispose()` → `Close()` → `Application.Exit()`；`Main` 里在 `Application.Run` 之后补一句 `Environment.Exit(0)` 兜底，保证进程一定干净退出。

网页版没有关窗口的权限，`DL.quitGame()` 会先试 `window.close()`，失败则在标题页底部显示 5 秒提示「浏览器不允许脚本关闭页面 —— 请按 Ctrl+W 关闭标签页」。

实测（打包版 exe，分别在标题页和全屏游戏中调用）：进程退出码 0，无残留 WebView2 子进程。

## 20. 平台定位：只做客户端

从这一版起，**唯一发行形态是 `光溺.exe`**，网页版不再作为目标平台维护。带来的取舍：

| 项 | 决定 |
|---|---|
| 运行载体 | .NET Framework 4.8 WinForms + WebView2，游戏本体仍是内嵌的 HTML/Canvas |
| 全屏 | 宿主窗口的边框状态，页面通过 `postMessage('fs:1'/'fs:0')` 请求 |
| 退出 | 页面 `postMessage('quit')`，宿主 `Application.Exit()` |
| 鼠标 | 一律走指针锁定 + 虚拟光标，破例回落到绝对坐标只在锁定失败时发生 |
| 存档 | `localStorage`（`drownlight.save.v1`），作用域是 `https://drownlight.local`，固定在 `%LOCALAPPDATA%\Drownlight\udf` |
| 网页兼容代码 | 保留但**不再作为支持目标**——`FS.host` 判定、`window.close()` 兜底这类分支只在宿主通道不可用时才会走到，属于防御性代码，不作为功能承诺 |

对后续开发的影响：

- 不必再为 `file://`、CORS、跨浏览器差异做妥协（例如不必再坚持“不用 ES Module”，但现有结构没必要为此重构）
- 新功能可以放心依赖宿主通道（存档、窗口、退出、后续可能的版本检查）
- 文档、README、构建脚本一律只描述 exe 一条路径

后续手感与细节打磨按用户节奏逐条进行。

## 21. 窗口图标与任务栏身份

### 21.1 问题

exe 从一开始就 `/win32icon` 嵌了图标，资源管理器里显示正常；但**任务栏、Alt-Tab、任务管理器里是 WinForms 的通用图标**。原因很简单：WinForms 的 `Form.Icon` 默认是 `null`，窗口会退回 `DefaultIcon`（那个灰底小窗口），而任务栏按钮、Alt-Tab 缩略图、任务管理器进程图标读的都是**窗口图标**，不是 exe 文件图标。

### 21.2 做法

- `icon.ico` 以托管资源 `app.ico` 的形式一起嵌进 exe（`/resource:...`）
- `OnHandleCreated` 里从资源流取出两枚 HICON：`new Icon(stream, 32, 32)` 给 `Form.Icon`（走 `WM_SETICON` 的 `ICON_BIG`），`new Icon(stream, 16, 16)` 直接 `SendMessage(WM_SETICON, ICON_SMALL)`；16×16 那枚存成字段，避免被 GC 回收后句柄失效
- 进程启动时 `SetCurrentProcessExplicitAppUserModelID("Drownlight.Game.1")`，让任务栏把它当成独立应用而不是混进 Chromium 那一堆

### 21.3 验证

从**运行中的窗口**取回图标句柄（`WM_GETICON`），存成 PNG 与 exe 文件图标比对，两者哈希完全一致 —— 说明窗口图标确实来自我们的资源，而不是系统默认。

### 21.4 没做成的一件事：版本信息

理想情况下任务管理器的「描述」列应该显示「光溺 DROWNLIGHT」，这需要 PE 里的 `RT_VERSION`（VERSIONINFO）资源。试过两条路：

| 路线 | 结果 |
|---|---|
| 自己拼 `.res` 交给 `csc /win32res` | `cvtres` 判为无效资源文件；按官方文档试遍了序号编码、对齐、HeaderSize 的组合，全部被拒 |
| 编译后用 `BeginUpdateResource/UpdateResource` 注入 | 注入成功，但 Windows 会把 VS_VERSIONINFO 重新规范化，回读出来的结构错位（Translation 的语种被读成 0x0000） |

结论：暂时不做。图标这一项不受影响；哪天需要，用 Resource Hacker 手工加一次，或者装上 Windows SDK 用 `rc.exe` 编译 `.rc`，都是十分钟的事。

weight = 稀有度权重 × (1 + min(1.9, Σ 已持有同标签等级 × 0.22 × 0.55))

## 24. v2.1 前置卡、渲染批处理、240Hz

### 24.1 卡牌前置（修一个真实的设计漏洞）

之前抽卡只看「等级未满」，于是会出现这种现象：**没拿光刃却抽到「双刃」「长刃」「刃舞」** —— 卡生效了，但因为 `s.blade === 0`，`drawBlade` 直接 return，既没有特效也没有伤害。玩家看到的就是「这张卡是废的」。

同类问题还有「锐利」（暴击伤害）—— 没有暴击率时完全无效。

修法：给卡加 `need: [卡 id]`，抽卡池过滤：

```
available(c) = 等级未满 && c.need.every(id => runCards[id] > 0)
```

受影响：`bladeLong / bladeTwin / bladeDance → need: ['blade']`，`critPow → need: ['crit']`。

这样「双刃」只有在拥有光刃后才会出现，一旦出现就一定有可见的横扫与伤害。

### 24.2 渲染批处理

| 项 | 之前 | 现在 |
|---|---|---|
| 灯锥 | 每帧 9 次渐变填充 + 9 次路径 | 整锥烘成半分辨率贴图，每帧 1 次 `drawImage`（长度/角度变化时才重建） |
| 粒子 | 每颗 1 次 `fill` + 2 次状态切换（最多 520 次） | 按「颜色 × 4 档透明度」合并路径，通常 10–25 次 `fill` |
| 海雪 | 每片 1 次 `fill`（约 460 次） | 按 3 档透明度合并，3 次 `fill` |
| 低画质 LOD | — | 实际帧率低于目标 95% 时，`D.glow` 直接跳过半径 < 34px 的小光晕 |

### 24.3 120Hz 逻辑 + 帧率目标

- 逻辑步长 60Hz → **120Hz**（`T.step`），高刷屏下运动明显更顺
- 新增设置 **帧率目标**：60 / 120 / 144 / 240
- 像素预算随目标收紧：240 → 230 万像素，144 → 310 万
- 自适应分辨率以目标为基准：低于 92% 降 10%，高于 99% 升 5%，240 帧时下限 0.5

实测（2560×1440，RX 7800 XT，`?bench=1` 的满场压力场景：Boss + 26 小怪 + 200 敌弹 + 480 粒子）：

| 目标 | 实际 | 峰值帧 | 内部分辨率 |
|---|---|---|---|
| 120 | 174–215 | 8.5ms | 2560×1440 |
| 240 | **240** | 4.3ms | 2022×1137 |

### 24.4 测试用的独立存档

新增 `--profile <dir>`：用独立目录跑自动化（`%LOCALAPPDATA%` 之外的 BaseDir），避免测试时的通关奖励写进玩家存档。之前的长回归把玩家存档的 `bestScore` 从 56,431 刷到了 352,693，已经回滚。

### 25.2 技能树“两个选中标记”

原因：`drawTree` 在**同一个循环里**一边检测悬停一边绘制：

```js
for (每个节点) {
  if (UI.hot(...)) UI.treeSel = m;   // 先改
  var isSel = UI.treeSel === m;      // 再用
  ...
}
```

鼠标从节点 A 移到节点 B 时，A 在本帧前半段已经用**旧的** `treeSel` 画过选中环，B 又用**新值**画了一次 —— 同一帧出现两个环。

修法：拆成两遍。先遍历一遍只为定下 `treeSel`，再遍历一遍绘制。

## 26. v2.3 Boss 池、每局随机 6 个、真正的无尽模式

### 26.1 问题

v2.2 之前「无尽深渊」只是标题界面的一个解锁项：`G.endlessRun` 从来没有被赋值过，
`doTitle(4)` 和 `doTitle(0)` 走的是同一条路 —— 玩家点了无尽，进去还是那 6 层。
同时 6 个 Boss 固定绑在 6 层上，第二局开始每一层遇到什么完全可预测。

### 26.2 Boss 池

- 池子从 6 个扩到 **12 个**（新增 锈 / 潮 / 眠 / 镜 / 鲸 / 晶），每个 Boss 只写自己的机制与绘制：
  - **锈**：`idle → tele(0.95s) → dash(0.54s) → stun` 的状态机，撞墙硬直更久并撒 5 枚腐蚀粘液
  - **潮**：30 颗一圈的浪墙，跳过前 6 颗留缺口；缺口每波 +0.95 弧度；缺口的亮楔只在新一波的前 1.4 秒显示
  - **眠**：`G.slowA` 全局减速场（按距离衰减，最多 −45% 移速）+ 雾 + 四臂慢弹 + 幻影
  - **镜**：三个固定锚点，`b.cur` 指真身，假身用 `drawMirrorGhost()` 画成空心；只有真身进伤害结算
  - **鲸**：横穿战场，`hitScale 1.05`、身体接触伤害；伤害按落点与眼睛（`DL.whaleEye`）的距离分档 ×1.6 / ×0.38
  - **晶**：6 个 `parts` 公转并各自开火，本体持续吐双螺旋；`partsAlive === 0` 时停摆 6.5 秒、受伤 ×1.5
- 数据里每个 Boss 带 `rank`（1~6，威胁等级），`sub` 只写物种名（层号改由 HUD 拼）

### 26.3 每局只出现 6 个

```js
DL.rollBosses = function (avoid) {
  // 洗牌 → 取 perRun 个 → 按 rank 排序
  pick.sort(function (a, b) { return (a.rank - b.rank) || (Math.random() - 0.5); });
  return pick;
};
```

- `DL.newRun(endless)` 抽一次名单存进 `G.runBosses`
- `startBoss()` 用 `(layer-1) % perRun` 取，**slot 归零且不是第 1 层时重新抽**（无尽换批，`avoid` 传旧名单）
- 排序保证名单里威胁最低的先出场：即使抽到 6 个高威胁 Boss，第 1 层也是其中最轻的那个

### 26.4 血量按层折算

```
base(layer) = rankHp[min(layer,6)]                    // 1~6 层
            = 3800 × 1.55^round × 1.055^(layer-6)     // 7 层起，round = ⌊(layer-1)/6⌋
hp = base(layer) × def.hp / rankHp[def.rank]
```

同一个 Boss 排到哪一层就有哪一层的血量，所以随机不会造成「第 1 层遇到 3800 血的终末体」。

### 26.5 无尽模式接通

| 位置 | 行为 |
|---|---|
| `UI.pendingEndless` | 标题选「无尽深渊」置 `true`，选「开始下潜」置 `false` |
| `DL.newRun(endless)` | 写进 `G.endlessRun` |
| 结算界面「再次下潜」 | 沿用本局模式（无尽里死了就再来一次无尽） |
| 波次状态机 | `if (!G.endlessRun && G.layer >= 6)` 才进结局 |

HUD 与 Boss 血条在无尽下会显示「第 N 层 · 无尽」「第 N 轮」，结算页多一行「遭遇 Boss」。

### 26.6 自动化验证

新增 `?bosstest=1&frames=N`：12 个 Boss 各跑 N 帧，记录最大弹幕数、部位数、HP 变化与异常；
再跑两条流程（普通模式打掉第 6 层 → `ending`；无尽模式打掉第 6 层 → 继续第 7 层），结果写进 `body[data-test]`。
实测 900 帧 × 12 个 Boss：无异常，最大弹幕 56（晶），部位数 6（晶）/4（群）。
